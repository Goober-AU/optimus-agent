# Upstream applicability review — 24 October 2026

Optimus is an independent Rust port. This review compares behavior and interfaces; it is not a merge/cherry-pick plan. Optimus baseline: `71ae54aef82d02d01f06eebc4e68e67dd7afd035`; working candidate: `release/v0.1.39`.

## Scope and evidence

Reviewed the relevant PrimeIntellect-ai **prime-agent** repository: 128 main-branch commits dated 10–24 October UTC, plus 44 non-PR issues updated in that window (7 open, 37 closed; 38 created in the window). Upstream main at retrieval: `5c898d1b27b109bd2d383c68d60a30536e39cc22`. Older open reports with activity in the window are included. This is not an audit of unrelated training, infrastructure or verifier repositories in the organization.

Read issue bodies and available comments, inventoried every commit below, and inspected selected implementation patches and corresponding Optimus paths. “Already addressed” describes the inspected path, not a claim to have reproduced every provider/OS scenario. Items marked “needs fixture” remain unconfirmed. No real credentials, paid model calls, user session mutations or upstream posts were used.

All 37 of the 37 closed issues contain the contribution bot's vouching auto-close message. Closure is **not evidence that a report was fixed or rejected after technical review**. Conversely, #3166 remains open even though a commenter identifies an upstream fix and passing test. State alone is unreliable in both directions. Each row links to its source, including the bot and human comments.

## What matters for Optimus

1. **Fixed in this candidate:** Python runtime dependency metadata (#3479). Normal bundled bootstrap installs dill separately, but direct runtime installation did not declare it. The existing locked version now belongs to installation dependencies.
2. **Dependency maintenance:** Tokio 1.53.1 was in the affected range of [RUSTSEC-2026-0386](https://rustsec.org/advisories/RUSTSEC-2026-0386.html). Candidate uses patched **1.53.3**, with a documented security exception to the seven-day age policy. No application AsyncFd constructor call was found; this is not a reproduced exploit. Prime moved to 1.54.1; that larger update is unnecessary here.
3. **Real capability/behavior gaps to address separately:** ACP session reload (#3667), bounded recovery from a reasoning-only length stop (#3703), and improved non-network kernel bootstrap error guidance (#3478).
4. **Highest-priority reproductions:** private saved-model authorization must never silently choose another model; dead-owner recovery must prove worker death/generation; tool-output secret filtering needs synthetic fixtures; stable request prefixes need cache diagnostics before changing prompt assembly.
5. **Already present in our implementation:** Windows Unicode clipboard bytes, OpenCode session headers, Bedrock event decoding, optional strict-tool support, live auth refresh, appended system prompt files, session-local harness directories, and configured default-model wiring.
