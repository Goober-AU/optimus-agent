## 2. RISK-RANKED GAPS

- P0-1 Session slash command wedge: `/goal status`, `/goal ship it`, `/autonomous status` never resolve `prompt`; the session stays wedged for its lifetime, including for later normal prompts. Pinned by `tests/long_session_soak.rs:2601-2671` (assert at :2662-2670, no `#[ignore]`); owners cited there: `core/agent_session.rs:7495-7497` (awaiting prompt) and `:9966-9969` (goal session-command branch). Handler DID run (result row present) - the await hangs after the result. Direct hit on "command appears to run but the runtime never returns to a usable state"; also hangs print-mode `prompt_and_wait` (`print_mode.rs:226-232`).
- P0-2 Ctrl+C abort discards user-queued turns: `queue_visible` defaults `false` in Rust (`core/agent_session.rs:8907`, per test comment) vs `true` in TS (`agent-session.ts:6141`), and `request_abort` cancels `!queue_visible` turns (`agent_session.rs:11064`). Pinned by `tests/long_session_soak.rs:2706-2836` (asserts at :2821-2835, no `#[ignore]`). The TS contract (`interactive-mode.ts:6989-7010`) is abort-preserves-queue.
- P0-3 Stale matrix test: registry has 43 commands incl. `occ` (`slash_commands.rs:428-433`, added in commit 0c8167c17, "release v0.1.33 with OCC controls"), but `tests/slash_command_matrix.rs:11-54` lists 42; `assert_eq!(names, COMMANDS...)` at :95 fails. The only "every command has a dispatch owner" guard is red, so `/occ` (and any future command) is unguarded by it.
- P1-4 Settings-selector persistence unverified and possibly unflushed: `native_host_settings.rs:383-416` calls `settings.set_*` with no `flush()`/`drain_errors`, unlike the flush-then-drain pattern in `native_host_commands.rs:477-489` (scoped-models Persist), `:773-781` (traces off), `:828-835` (traces on). No test reads settings.json after a selector change. UNCERTAIN whether `SettingsManager::set_*` is write-through (`core/settings_manager.rs` outside scope). If not, every /settings toggle is lost on restart - the exact KEY-RISK shape.
- P1-5 In-file parity list drift: `native_host.rs::every_dispatched_builtin_is_a_registry_name` :6574-6616 omits `jev`, `occ`, `stats`, `monitor` (and `side`/`quit`) while its doc claims "Every built-in the TypeScript dispatches" - same drift class as P0-3.
- P2-6 Hardcoded no-argument gate: `native_host.rs:3738-3758` lists 16 no-arg commands; registry `takes_argument=None` also covers stats, traces, monitor, effort, fast, ultrafast, login, heartbeas... (heartbeats). With-args forms of those dispatch to the handler (which errors with Usage) instead of falling to the model as TS does (comment at :3799-3802). Benign divergence today, drift-prone tomorrow.
- P2-7 Unicode separator parity (UNCERTAIN, TS side not readable in scope): `parse_slash_command` :517-560 uses Rust `char::is_whitespace()` (includes U+0085, excludes U+FEFF) where the ported JS regex `\s` is the opposite; `is_argument_separator` :59-61 is documented as `[\t\p{Zs}]` but accepts \v, \f, U+0085 as well. Affects `/name\u{85}x`-class inputs.
- P2-8 Soft catch-all: `native_host.rs:4570-4572` answers an unhandled registry command with a Status line ("/{other} is recognised but the native host has no handler for it yet.") - success-tone, not an error. Currently unreachable (all 43 commands have arms), but the failure mode is quiet.
- P3-9 Stale audit artifact: `tests/slash_command_matrix.json` records 42 commands, 9 UNHANDLED and 1 DIVERGES verdicts that no longer match the code (arms exist at `native_host.rs:4199`, `native_host_commands.rs:290-573`). Misleads future audits.
- P3-10 Doc nit: `native_host_settings.rs:40-42` says "the five callbacks" but `touches_the_daemon` :43-53 lists six variants.
- P4-11 Matrix owner detection is format-sensitive: `tests/slash_command_matrix.rs:66` only matches handler arms written as exactly 8 spaces + `"` - a formatting change to `run_builtin_command` silently breaks owner detection (partially self-tested at :150-167).

(P0) Abort drops queued work - `tests/long_session_soak.rs:2706` pins it; suspected cause `core/agent_session.rs:8907` (`queue_visible` default false) + `:11064` (abort cancels `!queue_visible` turns). What looks wrong: user-queued steer/followUp turns are cancelled by a plain abort; TS preserves them. 4. (P1, UNCERTAIN) `/settings` changes may not reach disk: `native_host_settings.rs:364-458` (`apply_local`) mutates the manager without `flush()`/`drain_errors`, while every other settings-writing command flushes and reports drain errors (`native_host_commands.rs:479-487`, `:775-780`, `:830-834`). Verify (test): back the mode's settings manager with a temp dir, `apply_change(Change::ShowImages(true))`, read settings.json from disk, recreate the manager, assert the value; also assert a simulated flush error surfaces to the user (the traces path does, the selector path cannot).

(P2, UNCERTAIN) `/stats foo`, `/traces foo`, `/monitor foo`, `/effort <bad>`, `/fast foo` etc. diverge from TS: TS sends no-arg commands with arguments to the model as text; Rust answers a Usage error (e.g. `native_host_commands.rs:298-299` for stats) because those names are missing from `no_argument_builtin_slash_command` (`native_host.rs:3738-3758`). Verify (test): classify `/stats foo` and assert the intended dispatch class matches the TS gate.
6. (P2, UNCERTAIN) Unicode separators: `/model\u{0085}x` parses as (model, "x") in Rust but would be an unknown command under JS `\s`; `/foo\u{FEFF}bar` is the inverse.
