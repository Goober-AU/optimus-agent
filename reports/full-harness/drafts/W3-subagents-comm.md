## 2. RISK-RANKED GAPS

**P0 — The PR #166 regression class is still not covered end-to-end.**
The supervisor half is fixed and tested: `agent_peer_summary` advertises `occ_capability` (`native_supervisor.rs:2253-2258`) with regression test `messaging_safety_supervisor_peer_listing_advertises_occ_capability` (`supervisor_messaging_safety_tests.rs:176`). The policy half is tested offline (`occ2_selection_wiring.rs` w01-w07) and the codec offline (`occ2_comm_fidelity.rs`). But the seam that joins them — `occ2_target_send_policy` (`subagent_runs.rs:169`) reading a REAL family listing and `wrap_outgoing_body` (`subagent_runs.rs:696`) producing the actual outgoing body — has no test. The only live delivery e2e (`tests/native_cli.rs:823 communication_activity_reaches_the_supervisor_roster_after_real_delivery`) hand-encodes the OCC-2 wire text at `:869-873` and never exercises negotiation. A regression in the peer lookup (`subagent_runs.rs:184-190`) or the spawn seam (`subagent_runs.rs:688-698`) would leave every real send silently on OCC-1 with zero test failures — exactly the failure mode PR #166 fixed.

**P1 — Family-reach enforcement is gated on the caller-supplied `agentOrigin` flag.**
`native_supervisor.rs:2831` reads `agentOrigin` from the public body; reach is asserted only when `agentOrigin && source_summary` (`:2858-2871` inactive-target path, `:2899-2913` live-target path). A client that sets `fromActiveSessionId` but omits `agentOrigin` still gets full sender attribution built from the roster (`:2929-2939`) with no reach check. The security model says family scoping is unchanged by OCC (`occ/mod.rs:6-9`); the supervisor is the transport authority here. All existing safety tests always pass `agentOrigin:true` (`supervisor_messaging_safety_tests.rs` passim). UNCERTAIN: parity with `daemon-supervisor.ts` not verified (out of scope). If intentional (client tools allowed to send "as" a session they can see), it is at minimum an undocumented trust decision needing a pinning test.

**P1 — Production OCC-2 can never engage; only the experimental `/occ 2` path can.**
`occ/selection.rs:493-497`: `validated_registry()` is honestly empty ("both sym-v1 and sym-v1-pt-pt-r1 ship samples = 0... An empty registry makes every send OCC-1"). Pinned by `occ2_selection_policy.rs::production_stays_occ1_while_nothing_is_evaluated` and `w01`. Any "true end-to-end OCC-2 test" (see task) MUST drive the experimental opt-in (`/occ 2` -> development policy) or inject evaluation records; a naive e2e test with defaults will assert an OCC-1 body and pass vacuously. This is a design fact, not a bug — but it is the single most important constraint on wave-2 test design.

**P2 — Name-addressed sends never negotiate OCC-2.**
`subagent_runs.rs:184-190` matches the target only against `agent.active_session_id == target || agent.session_id == target`. The agent-message surface advertises name selectors (the daemon resolves names: `native_supervisor.rs:2279` `summary.session_name.as_deref() == Some(selector)`), so a send addressed by session name succeeds but silently pins to OCC-1 even with `/occ 2` on and a capable peer. Fix is likely to also match `session_name`, or document the id-only rule.

**P2 — Child failure propagation is best-effort.**
`settle_child_run` publishes the failure terminal notice via `defer_rlm_terminal_notice`; on error only `eprintln!("Could not publish subagent completion: {error}")` (`subagent_runs.rs:874-876`; same pattern for deletion notices at `:231-241`). The parent model can finish its turn never learning the child failed. The run row still shows status "error" (visible via roster/collect), so this is observability degradation, not data loss.

**P3 — Double publication of daemon-hosted child sessions.**
`options.on_session_published` is invoked inside `DaemonSubagentHost::create_rlm_subagent_runtime` (`daemon_subagents.rs:172-174`) AND again in `execute_child_run` (`subagent_runs.rs:641-646`). The closure is re-entry tolerant (publication resolve is idempotent; cancelled/retained re-checked, `subagent_runs.rs:407-433`), so the second call is belt-and-braces — but nothing pins that tolerance, and a future change to the closure could double-fire aborts.

**P3 — Cross-worker OCC-2 is root-to-root only.**
`list_agent_peers` lists only each other live worker's root session (`native_supervisor.rs:2649`: `root_active_session_id`), so a subagent hosted in worker B can never advertise capability to a peer in worker A; those pairs are structurally OCC-1. Conservative and commented at `subagent_runs.rs:105-107` ("anything missing keeps the send OCC-1"), but no test pins the boundary.

**P3 — Roster snapshot absentee sweep is conservative when the ledger is unreadable** (`native_supervisor.rs:1060-1074`, comment at `:1052-1059`): stale child rows can outlive a snapshot. Documented in code; unpinned by tests.

**P3 — `REQUEST_TIMEOUT` is 24h** (`native_supervisor.rs:87`): a wedged worker can hold a cross-worker `send_message` for a day. Matches the TS constant per port comments; no test pins a cancellation/timeout story for the sender.

**P4 — Supervisor `send_message` TOCTOU between `summary_for_active` and the forward** (`native_supervisor.rs:2818-2929`): the roster row can change mid-resolution; the journal records uncertainty rather than guessing on lost responses (`:2947-2958`), so the residual risk is a stale-but-valid send. Acceptable.

## 3. SUSPECTED BUGS

**BUG-1 (P2, likely): OCC-2 negotiation skipped for name-selected receivers.**
- Where: `crates/pi-coding-agent/src/core/agent_session/subagent_runs.rs:184-190`.
- What looks wrong: `find(|agent| agent.active_session_id == target || agent.session_id == target)` ignores `agent.session_name`. The same send succeeds by name through the daemon (`native_supervisor.rs:2279` matches names), so identical messages take OCC-2 when addressed by id and plain/OCC-1 when addressed by name — silently.
- Reproduce/verify (test): build an `AgentSession` with an `agent_message_controller` whose `list_agents()` returns one agent `{active_session_id: "a1", session_id: "s1", session_name: "worker", occ_capability: Some(here())}`; enable `/occ 2` (development policy) with a >floor message; call `occ2_target_send_policy("worker", big_message)`; assert current behavior returns `Occ2SendPolicy::disabled()` while `occ2_target_send_policy("a1", ...)` returns an enabled sym-v1 policy. If confirmed as unintended, fix by adding `|| agent.session_name.as_deref() == Some(target)`.

**BUG-2 (P1, verify parity): family-reach bypass when `agentOrigin` is absent.**
- Where: `crates/pi-coding-agent/src/modes/daemon/native_supervisor.rs:2831` (flag read), `:2858-2871`, `:2899-2913` (reach checks), `:2929-2939` (sender attribution still applied).
- What looks wrong: reach (`assert_agent_family_reach`) is enforced only under `agentOrigin == true`, but the trusted-sender attribution and the forward happen regardless when `fromActiveSessionId` resolves. A local client can deliver a message attributed to an unrelated session it can merely see (visibility-filtered by `visible()`), bypassing the parent/sibling/child scope the model of `occ/mod.rs:6-9` promises.
- Reproduce/verify (test): extend `supervisor_messaging_safety_tests.rs::messaging_safety_supervisor_rejects_self_unknown_and_unrelated` with a variant that omits `"agentOrigin": true` but sets `fromActiveSessionId: "source"`, targeting the unrelated-depth-2 child. Today it likely forwards (no reach check). If TS parity demands the same, pin it with a comment; if not, enforce reach whenever `fromActiveSessionId` is present.

**BUG-3 (P3, behavioral): duplicate `on_session_published` invocation for daemon-hosted children.**
- Where: `crates/pi-coding-agent/src/modes/daemon/daemon_subagents.rs:172-174` plus `crates/pi-coding-agent/src/core/agent_session/subagent_runs.rs:641-646`.
- What looks wrong: the same publish closure runs twice per daemon-hosted spawn. The closure (`subagent_runs.rs:407-433`) re-reads `run.status == "cancelled"` and `retained_stop_ids` on each call, so under a race the second call can fire `abort()` or `request_retained_stop` a second time; `create_agent_message_deferred().resolve()` being called twice is assumed no-op (implementation not in scope).
- Reproduce/verify (test): fake `SubagentRuntimeHost` that counts `on_session_published` calls; run `start_rlm_child_run`; assert exactly one invocation (currently two), or document the re-entry contract with a test that a cancelled-in-between second publish does not double-abort.

**BUG-4 (P2, observability): child failure/deletion notices can be lost with only an stderr record.**
- Where: `subagent_runs.rs:874-876` (completion/failure notice), `:231-241` (deletion-failure notice), `:226-228` (deletion notice).
- What looks wrong: `defer_rlm_terminal_notice` failures do not feed back into the run row or any retry; the parent model's context may end without the child's terminal state.
- Reproduce/verify (test): unit-test `settle_child_run` with an injected notice sink that errors; assert either a retry, a run-row error marker, or (if accepted) pin the stderr-only behavior explicitly.

**BUG-5 (P4, UNCERTAIN — needs runtime check): assistant usage attribution may double-count on replayed `message_end`.**
- Where: `subagent_runs.rs:671-679` — every non-error/aborted child `message_end` triggers `attribute_child_completion`, which appends child usage onto the parent row (`:714-760`).
- What looks wrong: if the child event stream replays a `message_end` (e.g. reconnect/resubscribe), usage is attributed again because the lookup matches by content key.
- Verify (test): synthetic second `message_end` with the same assistant message; assert no double `append_child_usage_attribution`. Static analysis only — mark UNCERTAIN until run.

**Not bugs, verified:** double-publish tolerance logic (`subagent_runs.rs:413-431`) correctly handles cancelled-after-publish; `handle_worker_frame` source check (`native_supervisor.rs:532-536`) prevents stale-client frame injection; `agent_message_delivery_record_from_response` (`:3977-4030`) correctly maps unknown receipt status to Uncertain; `session_settings::enabled` fails closed on load errors (`occ/session_settings.rs:128`) while missing preferences default on (`:32-35` Default true) — intentional per tests.
