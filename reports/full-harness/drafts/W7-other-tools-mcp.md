## 2. RISK-RANKED GAPS

- **P0** — none found in the audited files. No fabricated-success, missing-result, or duplicate-side-effect path was identified in static reading; failure paths return `Err` (`edit.rs:570,580`, `acp_mcp.rs:68`, `attach_image.rs` ensure! guards).
- **P1 — MCP/ACP execute paths have zero test coverage.** `create_acp_mcp_tool_definitions` (`tools/acp_mcp.rs:111`) builds two execute closures per server; only `execution_result` and name validation are tested (`tools/acp_mcp.rs:222-313`). A regression in the generated Python code (e.g. quoting of `tool`/`arguments`) would ship silently. rg over `tests/` for `mcp_list_tools|mcp_call_|AcpMcpServerConfig` = only the source file itself.
- **P1 — no integration test invokes the `edit` tool with real arguments.** rg `("edit", json` over `tests/` returns nothing. The edit tool's only coverage is in-file unit tests (`tools/edit.rs:790-1043`); the full chain (prepare_arguments → schema validation → mutation queue → write → result) is never exercised together.
- **P2 — non-UTF-8 file handling diverges between preview and execution.** `execute_edit` reads with `String::from_utf8_lossy` (`tools/edit.rs:598`) so invalid bytes become U+FFFD and are written back (silent corruption); `compute_edits_diff` reads with `tokio::fs::read_to_string` (`tools/edit_diff.rs:848`) which errors on invalid UTF-8. The preview shows an error while execution corrupts. See SUSPECTED BUGS #1.
- **P2 — invalid `mcp_call_` arguments are not rejected locally.** `tool` non-string coerces to `""` (`tools/acp_mcp.rs:176-180`), missing `arguments` defaults to `Value::Null` (`:181`). Schema (`:212`) says both required and typed, but if upstream validation is absent or lenient the call reaches the kernel with empty tool name / `None` args. See SUSPECTED BUGS #2.
- **P2 — attachment concurrency unverified.** `create_attach_image_tool` sets `ToolExecutionMode::Sequential` (`tools/attach_image.rs:93`) but no test exercises two attach calls in one turn or attachment while another tool writes the same file. Temp-file spill cleanup after abnormal exit is unowned (`tools/output_accumulator.rs:25-40`).
- **P3 — cancellation granularity.** `execute_edit` checks the token only before access and after access (`tools/edit.rs:569-571`, `:594-596`); a cancel arriving after the second check still writes the file. `attach_images` checks per path and once at the end (`tools/attach_image.rs:31`, `:79`); the resize step ignores the token.
- **P3 — edit retry semantics rely on oldText mismatch.** A retried identical `edit` call after success fails with "Could not find the exact text" (no duplicate side effect — good), but nothing tests this end-to-end; a regression in `apply_edits_to_normalized_content` matching would allow double application.
- **P3 — truncation callers unverified for JSON/exit-code preservation.** `truncate_head`/`truncate_tail` cut at line boundaries only (`tools/truncate.rs:83-167`, `:169-251`), which preserves exit codes (kept by callers) but can split a multi-line JSON document; whether callers (bash/ipython, out of scope) append truncation notices correctly is untested here.
- **P4 — render fidelity regressions.** `get_edit_header_bg` (`tools/edit.rs:381-393`) returns no-op closures in all branches; error background colour never applied. `image_indicator_join` (`tools/render_utils.rs:244-246`) is an identity function.
- **P4 — mutation-queue key aliasing on Windows for not-yet-existing files.** `get_mutation_queue_key` canonicalizes when possible, else falls back to the un-normalized absolute path (`tools/file_mutation_queue.rs:116-132`); `a.txt` vs `A.TXT` on a case-insensitive filesystem yield different keys if the file does not exist at key time. Edit requires an existing file to read, so exposure is narrow.

## 3. SUSPECTED BUGS

1. **Preview/execute divergence on non-UTF-8 files (data corruption risk).**
   - Where: `tools/edit.rs:598` (`String::from_utf8_lossy(&buffer)`) vs `tools/edit_diff.rs:848` (`tokio::fs::read_to_string`).
   - What looks wrong: executing an edit on a file containing invalid UTF-8 (e.g. Latin-1 text or binary with a matching ASCII `oldText`) replaces every invalid byte with U+FFFD on write; the TUI preview of the same call instead shows `Error: stream did not contain valid UTF-8`. The user sees an error while the tool actually rewrites the file.
   - Verify as a test: write a file `b"caf\xe9\nline\n"`; call `compute_edits_diff` (assert error) and `execute_edit` (asserts it errors or preserves bytes). Current code: preview errors, execute writes `caf\u{FFFD}`. Decide the intended behaviour and pin it.

2. **`mcp_call_<server>` silently coerces invalid arguments instead of erroring.**
   - Where: `tools/acp_mcp.rs:176-181` (`tool` `.unwrap_or_default()`; `arguments` defaults to `Value::Null`), schema at `:212` requires both.
   - What looks wrong: if upstream schema validation is missing or bypassed (e.g. an extension calling the definition's `execute` directly, or a provider that skips validation), `tool: 42` becomes `""` and the kernel runs `mcp.call_tool(server, "", None)` — a confusing kernel-side traceback instead of a typed tool-input error. UNCERTAIN where validation is enforced (agent core, out of scope).
   - Verify as a test: build the definition from `create_acp_mcp_tool_definitions` with a mock provisioner; execute with `{"tool": 42, "arguments": {}}` and with `{}`; assert an `Err` naming the invalid field, not an empty-name kernel call.

3. **`execution_result` drops failure details and reports kernel stderr as the tool error.**
   - Where: `tools/acp_mcp.rs:62-68`.
   - What looks wrong: on `ExecuteStatus::Error` with captured stdout/stderr, the whole joined text becomes the `Err` message; `durationMs`/`status` details are lost (details JSON only built on success, `:70-79`). Not a correctness bug for the model, but error observability (duration, status string) disappears exactly when things fail.
   - Verify as a test: assert an error result still surfaces `status: "error"` and `durationMs` through whatever error channel `AgentToolResult` uses for failures (currently impossible from `Err(String)` — that is the bug to fix or document).

4. **`truncate_tail` byte accounting counts only `\n`, not `\r\n`.**
   - Where: `tools/truncate.rs:132` and `:203` (`byte_length(line) + 1` for newline).
   - What looks wrong: for CRLF output (Windows tools), each kept line costs 1 byte less than reality, so `output_bytes` under-reports and the byte budget can overshoot by (#lines) bytes. TS parity argument may make this intentional (Buffer.byteLength on the joined string), but the joined output re-inserts `\n` only, so CRLF content is also silently converted to LF by tail truncation.
   - Verify as a test: `truncate_tail("a\r\nb\r\nc", {max_lines: None, max_bytes: 5})`; assert whether `content` keeps CRLF (currently `\n`-only) and whether `output_bytes` matches `content.len()` (currently it can differ).

5. **`get_edit_header_bg` is a three-way no-op (dead error styling).**
   - Where: `tools/edit.rs:381-393`.
   - What looks wrong: every branch returns a closure producing `String::new()`; the TS version applies `toolErrorBg` on preview error / settled error. Result: TUI never shows the edit error background, so failed edits look identical to successful ones apart from text.
   - Verify as a test: call `get_edit_header_bg(Some(&EditPreview::Error{..}), true, &theme)` with a recording theme; assert the error background is requested (currently never).

6. **`OutputAccumulator` temp files leak on abnormal exit.**
   - Where: `tools/output_accumulator.rs:25-40` (`default_temp_file_path` in `std::env::temp_dir()`), spill removal only on degrade (`:132-140`).
   - What looks wrong: nothing deletes a successfully spilled `<prefix>-<hex>.log` after the consumer is done; on crash or if callers forget, temp files accumulate. Cleanup ownership is undocumented in this file.
   - Verify as a test: assert the documented owner (bash/ipython callers) deletes the path after `close_temp_file`; add a test proving `full_output_path` is stable across `close_temp_file` (already asserted `tools/output_accumulator.rs` test `large_output_spills_to_temp_file_and_reports_path`) plus a deletion-contract test.
