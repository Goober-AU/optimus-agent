- Wired adaptive OCC-1 vs OCC-2 selection into both send seams: `occ2_target_send_policy` (S1 per-target sends, now message-aware) and `occ2_spawn_send_policy` (S2 spawn, now prompt-length aware) build a real `SelectionContext` and delegate to `select_with_policy` instead of the hardcoded `allow_unevaluated = true` negotiation. The production policy runs first and selects OCC-2 only for a validated dialect that wins on measured economics; the experimental `/occ 2` opt-in additionally routes unevaluated dialects through the development policy (SILO reference profile), still behind the small-message floor, the strike guard and the codebook amortization gate. Every other refusal (unknown listener, no shared dialect, strikes, negative savings) is final.
- Added the minimal durable dialect evaluation store (`occ2-evals.json` in the sender's session artifacts, atomic tempfile write, fail-open bounded read) feeding `SelectionContext.evaluations`; it ships empty, so production selection stays OCC-1 until a validated record lands, and a synthetic record flip is a file write.
- Extended the strike ledger with `occ2_strike_pair_incidents` (decay-applied) so send-side selection refuses a pair after any recent decode failure, matching the listener-side delivery enforcement.
- The `AgentSessionMessageController::occ2_send_policy` trait member now receives the outgoing message body (the small-message floor needs it); the default implementation remains the conservative disabled policy, so implementors that do not override it keep OCC-1 behavior unchanged.
