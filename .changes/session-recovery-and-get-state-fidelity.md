- Fixed a session file whose first line is torn or header-less being destructively reset on open: the damaged bytes are now quarantined beside the fresh session as `<file>.corrupt-<timestamp>` (an unloadable file that cannot be quarantined fails the open instead of losing data), and an empty file still resets in place without a sidecar.
- Fixed `fork_from` swallowing per-line write errors: a full disk or permission failure now fails the fork with an error, and the partial target file is removed instead of lingering as a truncated fork a later open would silently "repair".
- Fixed the session manager's private atomic writer ignoring its `fsync` option: the temp file is now flushed to storage before the rename when requested. Session rewrites deliberately keep `fsync: false`; the RLM delivery boundary already provides its own append -> drain -> fsync durability, so no rewrite path gains a blanket fsync.
- Fixed the supervisor's `get_state` roster fallback serving a zeroed `sessionActions` placeholder as if it were authoritative queue state: the fallback response is now explicitly marked with additive `stale: true` and `fallback: "roster"` fields (backward compatible; unknown fields are ignored by existing clients), and a worker answer that already carries `sessionActions` keeps them through the supervisor's summary remap instead of being zeroed.
- Fixed the session lease guard's never-set `compromised` flag: a release that detects the guard was taken over through the 5s stale window no longer removes the successor's guard directory, closing the double-removal window that could admit a third acquirer while a second still runs.
