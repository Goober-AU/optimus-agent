Added: daemon-side OCC-2 capability advertisement and a live SYM communication indicator, completing the v0.1.32 communication-indicator wiring over real OCC-2 traffic. `create_agent_message_agent_summary` (crates/pi-coding-agent/src/modes/daemon/daemon_mode.rs) now advertises `OccCapability::here()` (the shipped sym-v1@1 card only) through a new `occ_capability_for` helper instead of `occ_capability: None`: the helper reads the session's `agentCommunication.occ2Enabled` setting through `DaemonSession::settings_manager` (the same seam `set_transport` uses), so the field is present exactly when the flag is on and absent means OCC-1 (negotiation yields no dialect, sends stay OCC-1). The passive-RLM summary literal in `create_agent_message_list_result` advertises through the same helper via the resident root's session settings, since every session in one daemon shares the codec build; a fully saved passive tree has no resident settings source and stays conservative (absent = OCC-1) - that plumbing gap is intentional and reported. The interactive indicator row (crates/pi-coding-agent/src/modes/interactive/communication_activity.rs) activates the reserved SYM slot as a third pulse: `CommunicationKind::Symbolic` deliveries now light "TXT/OCC/SYM" index 2 exactly like occ1 lights index 1 (same dedupe, family scope and 700ms PULSE lifetime), while `CommunicationKind::Latent` stays reserved and ignored (no producer exists; a LAT indicator is never rendered). The summary-line renderer needed no change; a parallel width pin was added in subagent_summary_line.rs for the three-slot string. Telemetry reflects the wire, not the flag: the roster projection (`from_admitted_messages` -> `communicationActivity`) reports kind "symbolic" only for delivered bodies that decode through the strict OCC-2 symbolic path, and never consults the settings flag - so with `occ2Enabled` off (the default, where this daemon never sends OCC/2 itself) SYM can only light for externally-authored OCC/2 bodies, which is the intended behavior. Tests: a roster round-trip over a real `occ2::encode_dual` payload asserts `deliveries[0].kind == "symbolic"` through roster view and agents-view projection with content-free checks (daemon_session_list.rs); the existing occ1 wire-equality test stays green; TUI tests pin the symbolic pulse on the SYM slot, latent-kind data being ignored and never rendered, and the three-slot indicator format.
