- Added capability-gated, daemon-owned OCC session preferences (`occ_get_preferences` / `occ_set_preferences`, schema revision 41): the daemon persists the per-chat OCC-2 toggle in its own session artifacts, so clients with a different agentDir, working directory or filesystem can no longer write a preference the daemon never reads. `/occ` uses the daemon RPC when `occ_session_preferences` is advertised and keeps OCC-1 available otherwise.
- Changed the daemon advertisement so pre-41 `occ2_communication` (global-settings storage semantics) is no longer advertised; older clients now see a visible "not supported" warning instead of a silent no-op, and older daemons answer "Unknown daemon command" to the new commands while new clients fall back to the historical local write with an explicit warning.
- Added OCC-2 preference provenance to daemon reads (`inherited`, `sourceSessionId`) and a daemon-authoritative echo on writes (`applied`, `scope`, `effectiveForNewMessages`); `/occ status` and the set confirmation render that host-reported truth, including the ancestor chat when the value is inherited.
- Registered `occ_get_preferences` / `occ_set_preferences` in the native supervisor's `DAEMON_COMMAND_TYPES` allowlist (110 -> 112): the supervisor validates every command before forwarding to the owning worker, so without the registration the worker arms were unreachable dead code for real `--mode daemon` clients and both live compatibility tests failed on their first OCC RPC. The offline contract test now pins the supervisor list so a worker-registered/supervisor-unregistered split cannot silently return.
