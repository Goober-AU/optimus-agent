Added: deterministic OCC-1 vs OCC-2 selection for agent messages (core/occ/selection.rs). A `SelectionPolicy` (production default: OCC-1 until a dialect carries an evaluation record with samples >= 30 and exact listener fidelity; development variant: the existing allow-unevaluated semantics with the SILO-profile token reference) drives `select_with_policy` over a `SelectionContext` of measurable inputs: listener capability, negotiated dialect, evaluation records, speaker/listener model ids, strike-ledger incidents, estimated message size, and codebook-in-context state. Measured fixed overheads from the offline cost analysis gate the decision (161-token codebook amortizes only over ceil(161/savings) expected remaining messages, 220-char small-message floor, corpus vs SILO token ratios), and `validated_registry()`/`validated_registry_with(records)` build a registry admitting only evaluated dialects - honestly empty today because both sym-v1 and the promoted sym-v1-pt-pt-r1 ship samples = 0. The send seams (subagent_runs.rs S1/S2, agent_messages.rs select_occ2_dialect) are untouched; the wiring patch is specified in reports/occ2opt/SELECTION-INTEGRATION.md for the owning lane, with strike input from the existing Occ2StrikeLedger and amortization from the codebook-in-context seam.
