Added: OCC-2 symbolic dialects as a second encoding of the `optimus.agent-comm.v1` contract. `core/occ/occ2.rs` encodes the same typed payload as OCC-1 behind a strict dialect header (`OCC/2 D=<dialect>@<version> C=<codebook sha256[:12]>`) with compact symbolic field lines; decode is strict (unknown dialect, version miss, codebook hash mismatch, malformed line, duplicate field, indexed gap => Err, never invented content), and dual payloads carrying a `#FALLBACK-OCC1` section must agree in both sections or are rejected. `core/occ/dialect.rs` makes dialects data, not code: a `DialectCard` (grammar, symbol table, sha256 over the canonical codebook serialization, speaker/listener model and task-type compatibility, metrics, fallback policy), a `DialectRegistry` with unknown-dialect => conservative OCC-1 fallback, and `OccCapability` negotiation between agents. The default hand-designed `sym-v1` dialect (TASK=T KIND=K STATUS=S FINDING=F EVIDENCE=E VERIF=V DEPENDS=D NEXT=N) is a starting point for the offline discovery engine; unit tests round-trip every scenario shape from the fidelity fixture and pin the sym-v1 codebook hash. Sender identity, daemon transport authority and plain-English default are unchanged.
