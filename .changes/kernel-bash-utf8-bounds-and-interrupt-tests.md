- Fixed multibyte UTF-8 characters being split into replacement-character pairs at the Python `bash()` output-buffer caps (512 KiB head boundary and 1.5 MiB rolling tail): both cut points now land on character boundaries, and a partial sequence dangling at the head cap is carried into the tail in stream order.
- Fixed concurrent `BashHandle._wait_reaped()` awaiters clobbering each other's wakeup: the completion notifier no longer hangs (silently dropping the `bash.completed` notice) when a cell awaits the reap alongside it.
- Fixed the Python kernel error event pushing an unbounded traceback into the ipython tool result: `evalue`/`traceback` are now capped at the kernel's 65536-character output budget with the standard truncation notice, matching stdout/stderr/result, so a huge exception can no longer deliver a ~1 MB traceback into the model-visible text.
- Added real-kernel bounds tests for the ipython tool result (2 MB stdout/stderr/result/traceback floods stay capped with notices, the kernel keeps serving, and raw fd writes land in background output instead of the cell's stdout), busy-kernel kill/restart coverage for the `KERNEL_RESTART_NOTICE` prefix, duplicate state-request id rejection, targeted interrupt parking before activation, and load-tolerant REPL startup/group-reap test timing on Windows.
