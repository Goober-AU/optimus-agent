- Wired the OCC-2 three-strike ledger into the production delivery path: every delivered agent-session message body now strict-decodes once through `create_agent_session_message_delivery` (ledger-gated), a failed decode records a strike for the (speaker, listener, dialect@version) pair, three strikes disable OCC-2 for that pair, and the embedded OCC-1 fallback section always delivers the payload - never dropped, never nulled.
- Persisted the strike ledger per listener session (`occ2-strikes.json` in the session artifacts, atomic tempfile write, fail-open on error): strike counts survive restarts, and counts decay to zero after a 24h quiet period so transient corruption cannot permanently disable a pair. A `/occ` preference write newer than the last strike clears the chat's ledger (re-arming OCC-2 starts from zero), and an explicit `occ2_strike_ledger_clear` is available for direct wiring.
- Added delivery telemetry recorded once per render in the durable message details (`occ2Delivery`: kind `symbolic` / `fallback_consumed` / `occ1_native` / `occ2_disabled_by_strikes` / `text`, pair key, strike flags), so consumers can classify without re-decoding bodies.
- Exposed `occ2_strike_pair_disabled` for the send-side selection path: a sender can check a target's persisted ledger before negotiating OCC-2 for that pair (selection-side consumption is a follow-up hunk in `subagent_runs.rs`).
