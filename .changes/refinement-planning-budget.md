Fixed refinement planning and review budgets that were clamped to extraction-sized limits and truncated against large-output models. The `session_before_refine` hook no longer reuses the memory `maxExtractionTokens` setting (4,096 by default) as the refinement-planning output budget: proposals embed full edit payloads (`old_str`/`new_str` with complete memory texts) and frequently exceed 8k tokens, so planning now uses its own default budget (min(32,000, model.max_tokens)) while `maxExtractionTokens` keeps governing memory extraction only.

The one-shot retry after a `Length`-stopped attempt now escalates straight to the retry ceiling instead of doubling the first budget: `max_output_tokens` is a cap, not a target, and doubling anchored the retry to whatever config clamped the first attempt - a live daemon saw 4,096 then 8,192, both truncated, against a 262,144-token model. The auto-refine review, previously single-shot with an immediate typed error on `Length`, gets the same one-retry-on-`Length` escalation with a 16,000-token ceiling (the review JSON is small, unlike full refinement proposals); a second `Length` still keeps the typed truncation error, and a retry that cannot raise the budget never runs.
